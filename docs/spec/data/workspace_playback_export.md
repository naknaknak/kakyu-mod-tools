# Workspace playback export

Scope update 2026-09-08: Event Player is original-only. The edited-Run UI
behavior documented below is historical; EP-08 owns its removal from the app.
Authoring bundles, semantic/coordinate proofs and headless package validation
remain supported by their owning tools. This decision changes no data schema
and does not claim that existing executable entry points have already changed.

Content Core 0.304.0 introduced local playback package v7, which every later Core
still writes (0.377.0 at this revision, TD-56; the additive blocks since then are
dated sections below). The v6 predecessor added
`workspace_binding` and authored UTF-8 text; v7 adds mapped event/resume
coordinates for message relocation while preserving
the v5 opaque/provenance boundary rules. Older schemas are rejected and must
be re-exported. The separately owned cross-repository package specification
remains at `kakyu-remake/docs/spec/tech/playback_package_schema.md`; this local
producer revision does not certify compatibility with a separately installed
remake version, and does not change that repository.

Original-only exports have an empty workspace binding. Authored exports carry
`kakyu_workspace_playback_binding/v2`: project/generation/manifest hashes,
source and effective member hashes, authored text counts and contextual Run
bindings. A fresh named workspace snapshot is reopened after projection and
must remain identical. Each changed callee requires its exact semantic proof;
changed shared dependencies remain unsupported. All source inputs are read-only.

Since Core 0.330.0 (2026-09-17) the contextual Run behind the export accepts
every authoring family and every stepped bundle. A same-size v2 proof of any
family (state literal, condition literal, resource name, choice option,
registered-definition call, shared-routine call, control target) binds by
identity after the byte-level checks (output identity, unchanged container
header, the patch bytes hashed, every other byte identical, the owner
instruction decoding structurally with the same operation and end in source
and output; the state family also re-decodes its literal). A message
relocation binds through the reproduced v4 coordinate binding as before. A
multi-step v9 bundle binds through its chain proof
(`kakyu_mes_semantic_diff_chain/v1`): the exporter needs the bundle itself
(the headless entry point passes the whole reopened bundle, not only its
proof), validates every step in order with the editor's own step-by-step
source check, and when the last step relocates uses that step's coordinate
binding, whose source coordinates are original coordinates because every
earlier step is same-size. A chain proof without its bundle fails closed.

The shared exporter projects the resolved effective MES. Text overrides require
an exact message offset and original raw-text hash; every declared override must
be consumed. A text operand with `s` and `source_hex` indexes authored UTF-8 while
retaining the source CP932 message for the byte-oriented analysis adapter.
Playback text comes from the UTF-8 string table. It must never be regenerated by
encoding authored text to CP932. Text indices and retained hex are validated.
The form of those strings (no BOM, NFC, no control characters, the fixed
CP932-to-Unicode mappings) is in [Text Encoding](text_encoding.md).

Every manifest and member is hashed, staged, reopened and published only to a
new destination. Workspace members must agree with package entry identities,
even after a modified manifest is rehashed. The resulting package contains
user-owned original content and is **local-only**, not a distributable mod delta.
Media extraction is explicitly deferred (nothing is extracted) and standalone
completeness is false. Since Core 0.373.0 the manifest also inventories every
media and script dependency of every member, with the identity of what the
original archives ship and the names they do not (see "Media inventory and
script references" below), so the deferral is a report, not an unknown.
Terminal owners absent from the package are inventoried as external terminals;
the caller completion boundaries those rows name remain deferred. The list
depends on the export's membership: the full original export (Core 0.373.0, 681
events from 869 members) has none, because the day scripts `12C.MES` and
`13C.MES` are analysis-group members now, while an export of selected events
(`--event`) lists every terminal whose owner entry is not among its members.

## Membership, Core 0.323.0

By the owner's ruling (a) of 2026-09-16 the full original package carries
every `mes.arc` entry a committed analysis-group profile under
`config/event_catalog/analysis_groups/` lists as a source member, in addition
to the catalog events' members. The catalog stays the playback-qualified
subset: `manifest.events` lists only catalog events, and the analysis-group
entries are carried so that the event-definition producer can resolve every
member of a qualified route. Measured at Core 0.323.0 over 138 profiles: 216
distinct source members, 5 of them already catalog members, so the package
grew from 17 to 228 entries (211 with role
`analysis_group_member`); 81,521,185 bytes, 246,930 records, exported in
67 s.

The schema string stays `kakyu_playback_package/v7` because the change is
additive: a consumer that does not know the new blocks plays the thirteen
catalog events exactly as before, and the `kakyu_event_definition/v3`
contract pins the v7 string. The manifest gains `membership` - `rule`
(`catalog_events_and_analysis_group_members` for a full export,
`selected_catalog_events` when `--event` or `--no-analysis-groups` narrows
it), the counts of catalog events, catalog members and analysis-group
members, and one row per profile (`profile` = file stem, `group_id`,
`schema`, `payload_sha256`; a group id may repeat across schema versions, a
payload hash may not) - and `incompleteness` - `standalone_complete` false,
`media_extraction` deferred, `external_terminals` as the workspace binding
already lists them (`event_id`, `terminal_id`, `owner_entry`, `offset`) for
every catalog terminal whose owner entry is not a member. Each entry report
carries `bound_by`, the sorted profile stems that list it. Membership is
merged fail-closed: a profile that is malformed, two profiles with one payload
hash, or one entry with two fingerprints abort the export, and every member
is verified against the archive by the fingerprint the catalog or the profile
records. The reader recomputes the membership counts, the bound-by references
and the external-terminal list from the manifest and rejects a manifest whose
blocks disagree; a v7 manifest without the blocks still loads. Entry names
with interior dots (`GROUND.INC.MES`) are accepted; upper case, one `MES` or
`LIB` extension and no empty segment remain required. Five operand fields
the runner copies into the trace at the inline-script-execution and
native-state-transfer boundaries (`execution_role`, `transfer_selector`,
`snapshot_selector`, `mapping_string`, `mappings`, first met in `START.MES`
and `43C.MES`) are kept; the fail-closed operand classification is otherwise
unchanged, and the package plays the thirteen catalog events identically
(the playback check's 82 checks, 251 boundaries and 509 payloads).

Since 2026-09-21 (EP-10 unit 5, Core 0.356.0) every catalog row is generated

Headless entry point:
`tools/content_suite/cli/export_workspace_playback_package.gd`, with arguments
`SOURCE_ROOT WORKSPACE_ROOT EVENT_ID AUTHORING_BUNDLE_OR_DASH NEW_OUTPUT_DIRECTORY`.
Use a dash for a workspace with no structural MES replacement.

The v7 event descriptors use effective start, choice, terminal and owned resume
coordinates. The workspace binding retains source/output points in contextual
binding v2 for a message relocation, identity-preserved binding v1 for a
same-size edit of any family (`coordinate_policy`
`identity_preserved_state_literal` or `identity_preserved_same_size_patch`),
or binding v3 for a stepped bundle (`chained_same_size_patches`, or
`chained_same_size_then_relocation` with the v2 relocation fields; both carry
`chain_proof_sha256` and `step_count`). The package reader
cross-checks every descriptor against those point inventories even after a
manifest is rehashed. This producer schema change requires re-exporting older
packages; there is no in-place v6 reinterpretation or consumer compatibility claim.

Original-coordinate UTF-8 overlays map through the reproduced message binding
before record projection. Overlapping translations and unproved coordinates
fail closed. Package playback remains archive/Python independent. The original
relocation regression verifies the shifted MACHI handoff at 7100, UTF-8 text,
reopened delta content and rehashed coordinate mutation rejection.

## Catalog binding, 2026-10-06 (WD-21 unit 1)

The manifest's `source.catalog_id` and `source.catalog_revision` name the
catalog the packaged events came from. Since the split they were always
written as `""` and `0`: the exporter read a `document` key the catalog's load
result does not have. `build()` now takes both fields from the load result,
whose validation guarantees a lowercase slug id and a positive integer
revision, and `serialize()` refuses a build result whose catalog binding is
missing, is not an object, has no slug `catalog_id` or has no positive integer
`catalog_revision`. It also refuses a build result without `resource_names`:
`media.referenced_resource_names` is taken from the build result (sorted), not
from the exporter instance that happened to build it, so a serialization no
longer depends on which instance produced the build.

The schema stays `kakyu_playback_package/v7`; the two fields already existed,
so the change is additive. Because `package_sha256` covers the whole manifest,
a package's hash now changes whenever the tracked catalog's `catalog_revision`
is bumped (before, a catalog revision bump alone did not move it),
and a package exported before this revision carries the empty binding, so an
older hash does not equal a new export of identical content.

The reader is unchanged and does not read the binding: `manifest_error` and
`load_directory` never look at `source.catalog_*`, so a rehashed manifest with
the binding absent, empty and zero (the historical form), or of any other shape
still loads, and the manifest hash is the only integrity the binding has on the
read side. Checking its shape when it is present would be a Core change of its
own and is not part of this revision. The producer side is checked by
`tests/test_playback_package.tscn` (the tracked catalog's own load result is an
accepted binding; twelve malformed bindings, a missing one and a non-object
one are refused, as is a build result without `resource_names`; the absent and
the historical empty binding still load).

## Streaming build result, 2026-10-10 (TD-64 part 2)

`build()` no longer holds a package's documents. The 869-member full export held
every member's events and text documents as GDScript Variants (about 3.8 GB of its
4.0-4.9 GB of static memory) until `serialize()`. Each member is now serialized
(`_payload()`: the JSON bytes, their size and SHA-256) and fed to the media-identity
and inventory accumulators as soon as it is built, and its Variant documents are
dropped with the loop's next turn.

The build result carries `payloads[entry] = {events, text}`, each a `_payload()`
dictionary, and `inventory_evidence`, the inventory accumulator's `finish()`
(`KakyuPlaybackPackageInventory.begin`), beside the existing `media_identity` and
`media_scan` (`KakyuPlaybackMediaIdentity.begin`; `collect()` is its wrapper and
the order of its rows and failures is unchanged). It no longer carries `documents`
or `texts`. `serialize()` lists the payloads in the order the build made them
(events, then text, per member; the manifest last), builds the inventory blocks
with `build_blocks_from(inventory_evidence, ...)` and refuses a build result with
no payloads, a malformed or unserializable payload, no inventory evidence or
evidence that does not cover exactly the members its `entry_reports` name. It reads
no document, so there is one production path and no eager fallback.
`payloads_for(documents, texts)` runs the same per-entry function for a build
result that was not made by `build()` (the tests' fixtures).

The package files and the manifest are unchanged byte for byte; the schema and the
Core version are not touched by this revision (Core 0.376.0 belongs to the lazy
reader). `tests/test_playback_package.tscn` pins the payload bytes, the file order,
the copy semantics and the refusals, and `tests/test_playback_media_inventory.tscn`
pins the media-identity accumulator against `collect()` in every feed order.

## Media inventory and script references, 2026-10-06 (WD-21 unit 1)

Core 0.373.0 adds two optional blocks to the v7 manifest, `media_inventory` and
`script_references`, and derives the existing `media` block from the build result.
They make the package say, with source evidence, every media and script dependency
of every member, which of the media the original archives ship (with identity) and
which they do not. `incompleteness.media_extraction` stays the literal `deferred`:
nothing is extracted. The schema string stays `kakyu_playback_package/v7`.

**Schema ruling (D1, advisor, recorded here and in WD-21).** Both blocks are
additive optional v7 blocks, each with its own schema id - `kakyu_media_inventory/v1`
and `kakyu_script_references/v1` - so that a later change of the classifier rules is
an explicit incompatibility rather than a silent drift. There is no v8: a v8 would
fail every v6 event-definition document that pins the v7 string. This
repository's reader fails closed on a block whose id it does not know, recomputes
only the ids it knows, and ignores an absent block: a v7 manifest without them
still loads and makes no inventory claim. This is a statement about this
repository's reader only; it makes no claim about the reader of any separately
installed remake.

### The `media` block

Unchanged in shape: `extracted` false, the `boundary` text, `catalog_declared` and
`referenced_resource_names` (sorted, as written). `referenced_resource_names` is now
taken from the build result, not from the exporter instance that built it
(`serialize()` refuses a build result without it); the full original export's list is
the same 16,231 names the pre-WD-21 package carried, so the block did not move.

### `media_inventory` (`kakyu_media_inventory/v1`)

Fields: `schema`, `normalization` (`upper_case`: the one comparison every consumer
uses, the way `KakyuArcReader` matches entries), the three rule tables
(`kind_archives`, `extension_archives`, `bank_sets`), `archives`, `members`, `names`,
`scan_only`, `cross_check` and `counts`.

- **Kinds.** `mmo`, `ax`, `voice`, `se`, `a6`, `bgm` and `unclassified`. The rules,
  their evidence and what is a tool decision rather than a confirmed native meaning
  are in [Media Reference Classification](../mes/media_references.md).
- **Evidence basis.** The package's own records, for every kind. `members` lists, per
  member that has any, its occurrences `{at, kind, name}` (an `unclassified` one also
  carries its `evidence` label) sorted by offset; the reader recomputes this set from
  the member documents it has loaded. `LIBLARY.LIB` is classified over its routines.
- **Identity** (`names`, one row per `(kind, name)`). `shipped: true` with `rows`
  `{archive, entry, size, entry_sha256}`, one per archive that holds the name;
  `shipped: false` with `searched`, the archives of the kind, only when every one of
  them was opened and searched; `shipped: null` with `unavailable`, when an archive of
  the kind was not in the source root, so nothing is claimed. The full original export
  has no `null` row and the export CLI fails on one; a synthetic or workspace build
  tolerates it. `archives` is the header: the SHA-256 of every media archive the
  producer opened.
- **The Tina bank set** (tool decision). `tina1.arc` and `tina2.arc` are alternative
  voice banks the original chooses between with its `[Voice] TINA=1|2` setting. They
  are one declared bank set with no preferred bank, so a Tina name has two rows; the
  reader requires at least one row per occurrence. A name in a bank set and in another
  archive of the same kind is not a bank set and stops the producer.
- **The producer's scan cross-check** (`scan_only`, `cross_check`). The analysis
  scan's references (`mmo`, `ax`, `voice` and the `mes_script` names) are compared with
  the records. A `strict_indexed` hit that is not a record occurrence fails the export;
  a `bounded_envelope_scan` hit that is a record is counted separately from a
  `scan_only` hit that is in no record, which the manifest lists, looks up for identity
  and does not treat as an occurrence. The full original export has 6,738, 2,316,
  23,027 and 2 strict record-backed hits and no bounded or `scan_only` row.
- **Searching.** An absent name that exists in another media archive stops the
  producer (a rule that is wrong, not a known absence). `build()` pins the live
  SHA-256 of every archive it opens against the table in
  `content_core/original_archive_identity.gd` (the `tina1.arc` and `tina2.arc` pins
  were measured live on 2026-10-06): a source root holding a modified media archive
  beside the original `mes.arc` now **fails `build()`**; a root with only
  `mes.arc` (a synthetic run) opens nothing and records `unavailable`.

### `script_references` (`kakyu_script_references/v1`)

`targets`, one row per normalized script name - every `script_target` of any record
plus the `.MES`/`.LIB` names an `inline_script_execution` record names - each with
`member` and its `references` `{entry, at, via}`; `counts` carries `targets`,
`references`, `member_targets`, `non_member_targets` and `by_via`. The full original
export has 959 targets (853 members, 106 not), 8,226 references (7,344
`script_dispatch`, 880 `script_handoff_marker`, 2 `inline_script_execution`, naming
`DEF_MAIN.MES` and `LIBLARY.LIB`). **`member: false` is a report, not a membership
position**: package membership is unchanged, and the 13 `*_CG.MES` viewers that show
as `member: false` stay outside the membership. No CG table is exported: on
2026-10-09 the owner withdrew WD-21 U3 (the flag -> picture table of 2026-10-06), because
the pictures suffice. Of the 572 pictures the viewers load, 556 are `media_inventory` names
through member events. The viewers' 13 page pictures and three pictures no member names are
not, and are listed in `docs/spec/mes/gallery_families.md`.

### The reader

`KakyuPlaybackPackage.load_directory` runs the inventory check in the load's single
pass over the members and finishes it before the snapshot is committed, so a failed
load leaves the last verified snapshot. When either block is present it recomputes the
occurrence set and the script references from the members' documents, fed per entry
to the inventory accumulator as the load parses each one, and compares them with the
manifest; it checks the block's structure (exact keys, sorted, no duplicates), that the
rule tables equal its own, that every name any occurrence uses has an identity row and
no other does, that each identity row is in one of the three states with the shape and
archives that state requires, and that `counts` equals its rows. A mismatch, an unknown
schema id or a malformed block is refused, also after a rehashed manifest.

Since Core 0.376.0 (TD-64 part 2) the reader does not hold the package as parsed
documents. The load checks each member file's size and SHA-256 against the manifest and
**keeps the verified bytes**, parses the member transiently (the document check, the
inventory accumulator, a transient code source so that a document the source cannot
index still fails the load) and records the eager metadata: `code_size`,
`address_table`, the entry fingerprint and the role. `code_source(entry)` then returns one lazy shell per entry for the
life of the snapshot, which parses its entry from the kept bytes on the first call that
needs records, through a bounded cache of parsed sources (`source_cache_limit`, **32 by
default, a tool decision**, floor 1; `source_cache_stats()`); evicting a source frees its
parsed state and its next call parses again. No file is read after the load. With two
faults in one package the load reports the one that comes first in entry order; each
single-fault message is unchanged. `todo/code_health.md` (TD-64) has the measurements.

What the reader never does: open an archive, recompute identity, compare an identity
row or the `archives` header with a pinned value (it checks that each header value is a
SHA-256 and the archive is a media archive; **tool decision**: `build()` owns the pin, so
a later correction of a pin cannot make every exported package unreadable), or treat
`shipped: false` as an error - an absence is a known fact. Package-versus-register
agreement belongs to the validation gates, not to the reader.

### Cost and changes

Measured 2026-10-06 on the full original export (869 members, 987,386 records):
`manifest.json` 13,419,998 bytes against 7,580,550 before (`media_inventory` about
5.3 MB, `script_references` about 0.5 MB), package hash `b638bd7d...`; the registry
check `original playback package export` takes 309.5 s of 900 s run alone through the
runner (0.344; the previous export was 274.3 s); an export with `--out` takes 361.9 s,
53.3 s of it writing the 329.7 MB package and `write()` reopening it, which is a
one-off cost of a binding export and not a check. `--out` must be an absolute
directory: `write()` refuses a relative one after the build has finished. Reopening
the package with the reader takes 41.9 s, of which the inventory recompute is 10.7 s.

A change of `mes_bgm_catalog.gd`, of the loader or extension tables or of any
classification rule changes what the blocks mean, so it is a
`kakyu_media_inventory/v2`; the loader tables and the extension table are tool
decisions over measured observations. Because `package_sha256` covers the whole
manifest, a package exported by Core 0.373.0 has a different hash from the same content
exported before; the tracked v6 event-definition set was rebound to the new hash
(`b638bd7d...`) on 2026-10-06 (WD-21 U1 C4: only `package_binding.package_sha256` of
the 681 documents and `index.json` moved). *Note, 2026-10-08:* that is the history of the v6 set,
